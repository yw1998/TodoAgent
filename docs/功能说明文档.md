# TodoAgent 功能说明文档

## 1. 项目简介

TodoAgent 是一个基于消息平台的智能待办事项机器人。用户通过飞书（或其他 IM 平台）向机器人发送自然语言消息，例如"明天早上10点提醒我买菜"，后端服务调用大模型 API 进行意图理解与参数抽取（Tool Calling），自动创建待办事项，并在到期时通过飞书消息推送提醒。同时提供 Web 管理页面用于配置管理和待办事项浏览。

## 2. 目标用户与使用场景

| 场景 | 描述 |
|------|------|
| 日常提醒 | "明早9点提醒我打卡"、"每周一上午10点提醒我开周会" |
| 待办查询 | "我今天有什么待办？"、"列出本周所有提醒" |
| 待办修改 | "把买菜的提醒改到下午3点"、"取消周会提醒" |
| 完成确认 | "我已经买完菜了"（标记完成） |
| 管理员 | 通过 Web 页面配置机器人参数、LLM 密钥、查看系统运行状态 |

## 3. 功能列表

### 3.1 消息接入功能

- **F1 飞书消息接收**：接收用户在飞书中发送给机器人的单聊消息和群聊 @消息，支持文本消息类型。
- **F2 消息去重与幂等**：对飞书事件回调做去重处理，避免重复创建待办。
- **F3 通知目标自动记忆**（v2 单人化）：自动记住最后来消息会话的 open_id/chat_id 作为提醒发送目标，已移除多用户注册与归属逻辑。
- **F4 多平台扩展**：消息渠道层抽象，预留企业微信、Telegram、钉钉等渠道接入能力（可扩展，首期仅飞书）。

### 3.2 智能解析功能（LLM Tool Calling）

- **F5 自然语言意图识别**：调用大模型 API，识别用户意图，支持以下工具（Function/Tool）：
  - `create_todo`：创建待办事项（标题、提醒时间、重复规则、备注）
  - `list_todo`：查询待办列表（按时间范围、状态过滤）
  - `update_todo`：修改待办的时间/标题/内容
  - `complete_todo`：标记待办为已完成
  - `delete_todo`：删除待办
- **F6 时间解析**：由大模型结合当前时间上下文解析"明天早上10点"、"每周五下午3点"等相对/周期性时间，输出 ISO 8601 时间戳与 cron/RRULE 表达式。
- **F7 追问与容错**：无法确定时间或标题时，机器人主动追问（如"请问是明天还是后天早上10点？"）；LLM 调用失败时回复友好提示并支持重试。
- **F8 多轮上下文**：保留用户最近 N 条对话上下文（默认 10 条），支持"改到下午3点"这类省略主语的后续指令。

### 3.3 待办调度与提醒功能

- **F9 到期提醒**：调度器按提醒时间扫描待办，到期后通过飞书发送提醒消息（文本/卡片形式）。
- **F10 周期提醒**：支持每日/每周/自定义 cron 的周期性待办，每次触发后自动计算下次提醒时间。
- **F11 提醒确认**：用户回复"收到/完成/snooze 10分钟"等指令可确认完成或延后提醒。
- **F12 提醒失败重试**：飞书发送失败时按指数退避重试（默认 3 次），最终失败记录日志。

### 3.4 待办管理功能（用户侧消息指令 + Web 浏览）

- **F13 待办浏览**：Web 页面展示全部待办事项，支持按状态（待提醒/逾期/已完成/已取消）、关键字、时间过滤。
- **F14 待办详情**：查看单条待办的完整信息：原始消息、解析结果、提醒历史、下次触发时间。

### 3.5 Web 管理页面功能

- **F15 系统配置管理**：
  - LLM 配置：API 地址、模型名称、API Key、温度、超时时间
  - 飞书配置：App ID、App Secret、事件订阅 Verification Token / Encrypt Key
  - 调度配置：时区、提醒扫描间隔、重试次数
- **F16 配置热生效**：配置修改后无需重启服务即可生效。
- **F17 ~~用户管理~~**：v2 起为单人私人部署，已删除用户体系（users 表、用户页面、归属校验）。
- **F18 操作日志/消息日志**：记录收到的每条消息、LLM 调用结果、提醒发送结果，供排查问题。
- **F19 管理页登录鉴权**：管理员账号密码登录（JWT），防止未授权访问。

## 4. 消息交互示例

```
用户: 明天早上10点提醒我买菜
机器人: 已为你创建待办 ⏰
        「买菜」— 2026-10-17 10:00 (周六)
        到时我会提醒你。

（次日 10:00）
机器人: ⏰ 提醒：该买菜啦！(来自待办 #123)
        回复「完成」标记已完成，回复「延后10分钟」稍后再提醒。

用户: 完成
机器人: 好的，「买菜」已标记完成 ✅
```

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 消息处理端到端 P95 < 5s（含 LLM 调用）；提醒触发误差 < 30s |
| 可用性 | 服务可多副本部署；LLM 故障不影响已入库待办的提醒 |
| 安全 | 密钥类配置加密存储；Web 管理页需登录；飞书回调签名校验 |
| 可维护性 | 模块化分层，渠道/LLM/存储均可替换；关键流程有日志 |
| 数据 | SQLite（单机）起步，可平滑迁移 PostgreSQL |

## 6. 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 语言 | Python 3.12+ | |
| Web 框架 | FastAPI + Uvicorn | 异步，自带 OpenAPI，兼做管理后台 API |
| ORM | SQLAlchemy 2.0 (async) + Alembic | 迁移管理 |
| 数据库 | SQLite（默认） | 可平滑迁移 PostgreSQL |
| 调度 | APScheduler | 进程内调度，简单可靠；量大可换 Celery beat |
| LLM | OpenAI 兼容 SDK（可配任意支持 tool calling 的模型） | |
| 飞书 | 飞书开放平台：事件订阅（长连接或 Webhook）+ 消息 API | |
| 管理前端 | 服务端渲染 Jinja2 + htmx（轻量），或 Vue/React SPA（可选） | |
| 部署 | Docker / docker-compose | |
| 测试 | pytest + httpx | |
